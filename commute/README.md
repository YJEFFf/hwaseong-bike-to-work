# 끊긴 자전거도로와 공장 출퇴근 (2026-09-28 재설계 분석)

> **2026-10-22 수정:** 2026-09-14 OSM 추출 파일에 도로 1,723개 모두 공유 노드 번호(`nodes`)가 빠져 있어,
> 교량·터널 구간이 끊긴 것으로 계산됐다. `00_restore_osm_nodes.py`로 추출 시점의 OSM 공개 이력에서 번호를
> 되살린 뒤 03→02→04→05→07→06을 다시 실행했다. 주요 변화: 연결 덩어리 383→208, 20m 끊긴 지점 266→212,
> 50m 324곳, 일자리 몫 3.7→7.3%(최대 집계점 제외 5.5→11.0%), 둘 다 연결 17.0→21.8%(11.1→17.7%),
> 주요 일터 도달 40.5→44.8%, 상위 20곳 +23,212명(308m), 조건부 탄소 연 118~203tCO₂.
> 아래 '전체 재계산 결과' 표는 복원 전(09-28) 값이므로 현재 수치는 `results/`를 따른다.
> 공개본에는 복원 전(09-28) 값이 남은 `bundle_target_sensitivity.csv`·`recalculation_validation.json`과 09-28 검수·재계산 기록을 넣지 않았다.

**9/29 현재: 전체 재계산 완료.** 공유받은 공장 원본·최종 캐시·수동 보정표로
02~07과 접속 300m 민감도를 실행하고 `results/`·`figures/`를 갱신했다.
최대 종업원 집계점 제외 시 공장 진입 효과는 **7.2→8.1%**, 틈 연결과 함께하면
**10.2→11.1%**다. 기존 코드의 핵심 CSV 8개도 같은 입력으로 정확히 재현했다.
09-28 교차 검수와 전체 재계산 기록은 팀 비공개 저장소에 있다.

보고서 주제는 「일터까지 이어지는 자전거길: 화성시 끊긴 자전거망과 '자차 출퇴근' 채용공고로 찾은 탄소 감축 기회」(2026-10-22)다. 채용공고 분석은 `../jobs/`에 있다. 화성시를 데모 도시로 삼아 다음 세 가지를 계산한다.

- 두 지도(공식 GIS, OpenStreetMap)를 겹친 자전거망에서 **끊긴 지점**
- 근로 연령(20~64세) 주민이 **가까운 공장 일자리에 자전거로 닿는 몫**
- **어디를 먼저 이어야 하는지**

경로 계산은 저장소의 `analysis/`와 `scripts/10_auto_scenarios.py`를 불러 쓰고, 기존 코드는 고치지 않는다.

## 실행 (저장소 루트에서, Windows는 `PYTHONUTF8=1`)

Python 3.12 환경에서 `python -m pip install -r requirements.txt`로 의존성을 설치한다. 공장 엑셀을 읽는 `openpyxl`도 포함돼 있다.

```
python -X utf8 commute/scripts/00_restore_osm_nodes.py   # OSM 파일의 빠진 노드 번호 복원(교량·터널 접속). 10/22 추가, 반드시 먼저
python -X utf8 commute/scripts/01_geocode_factories.py   # 공장 주소 → 좌표(브이월드), 캐시는 FACTORY_DIR
python -X utf8 commute/scripts/01b_geocode_retry.py      # 실패 주소 재시도
python -X utf8 commute/scripts/03_gaps_and_shared.py     # 연결 덩어리·끊긴 지점·보행자 겸용
python -X utf8 commute/scripts/02_commute_access.py      # 출퇴근 도달(ACCESS_M=300이면 접속 반경 민감도)
python -X utf8 commute/scripts/04_gap_priority_commute.py  # 끊긴 지점 우선순위·묶음 효과·조건부 탄소
python -X utf8 commute/scripts/05_factory_distance.py    # 공장 일자리의 자전거 시설까지 거리
python -X utf8 commute/scripts/07_sensitivity.py         # 진입 구간 규모, 최대 사업장·근사 위치 제외 민감도
python -X utf8 commute/scripts/06_figures.py             # 그림 1·2
```

- 입력은 `outputs/runs/loo_work`(저장소 재실행 작업 폴더)의 망·인구·행정경계다.
- **팀원:** 비공개 작업 레포(ai-transport-contest-2026)의 `Claude_작업기록/13_재설계_출퇴근_0927/private_data/factory_202402/`에 원본·최종 좌표 캐시·수동 보정표가 있다. 제출레포를 작업 레포 폴더 안(`제출레포/`)에 두면 자동으로 찾는다. 다른 위치에서는 `FACTORY_DIR`로 지정한다. 캐시를 사용하면 키 없이 **03→02→04→05→07→06** 순서로 실행한다.
- **외부 재현:** 공장 원자료는 이 제출레포에 없다. 화성시 공장등록 현황(2024-02)은 [화성시 게시물](https://www.hscity.go.kr/www/user/bbs/BD_selectBbs.do?q_bbsCode=1183&q_bbscttSn=20240311115327146)의 첨부파일로 받는다. 이 파일에는 연락처 열이 있다. 받은 파일은 `FACTORY_DIR` 환경변수가 가리키는 폴더에 둔다.
- 공장 주소를 새로 좌표로 바꿀 때만 브이월드 지오코더 인증키가 필요하다. 키는 `VWORLD_KEY` 환경변수나 `~/.vworld_key` 파일에 둔다. 현재 [이용약관](https://www.vworld.kr/v4po_prcint_a001.do)의 관련 규정은 **제19조**다. **공장 원본·변환 좌표는 제출레포에 올리지 않는다.** 보관·공유는 이용조건을 충족해야 한다. 공개 망에서 유래한 결과 좌표의 재배포 조건은 별도로 [DATA_LICENSES.md](../DATA_LICENSES.md)와 대조한다.
- 당시 결과 재현에는 같은 `geocode_cache.csv`와 **`manual_geocode.csv`도 필요**하다. 01/01b는 수동 보정표를 만들지 않는다. 수동 표의 열은 `pattern,x,y`이며 실제 보정 기록을 `FACTORY_DIR`에 둔다. 빈 표를 만들어 기존 결과가 재현됐다고 간주하지 않는다.
- `COMMUTE_OUT`으로 결과 폴더를 분리할 수 있다. 03을 먼저 실행해 `gap_id`, 양 끝점·계층, 반올림 전 거리를 생성한다. 같은 환경변수를 나머지 스크립트에도 적용한다. 06은 같은 결과를 읽고 `COMMUTE_FIG`에 그림을 저장한다. 한글 글꼴은 설치된 글꼴 중 자동 선택하며 `COMMUTE_FONT`로 지정할 수 있다.
- 좌표를 붙이지 못한 공장은 세 가지 방법으로 보완했다(종업원 기준). 전체 종업원 중 좌표를 붙인 비율은 99.4%다.
  - 수동 보정 1개 규칙(공장 원본 3행에 적용): 반월동 산16을 도로명 삼성전자로 1로 바꿨다.
  - 같은 산업단지 공장들의 평균 위치
  - 같은 읍·면의 리 또는 같은 동 공장들의 평균 위치(이름이 같은 다른 읍·면의 리는 구분)
- 통근 수단(인구총조사 2020·2015, KOSIS DT_1PA2003·DT_1PA1503)은 `data/`에 있다.

새 상위20은 기존 20곳과 **7곳이 다르다**. 344→241m는 선택 대상 변화가 포함된 값이다.
기존 20곳을 고정하면 344m·28,317명, 기존 OSM-공식 4곳 제외 시 317m·16,727명은 유지되고,
탄소의 종합 범위만 약 **111~248tCO₂**가 된다. `bundle_target_sensitivity.csv`에 두 목록을 구분했다.
새 목록에서 출처혼재 1곳도 추가 제외하면 14곳·208m·15,515명이다.

한계:
- 공장등록은 제조업만 담는다.
- 결과는 거리 기반 잠재량이다.
- 상위20은 항공영상에서 모두 판독불가였다. 실제 단절·통행 가능성은 아직 확인하지 못했다. 241m는 모델의 직선 연결 합이며 검증된 공사 물량이 아니다.
- 넓은 사업장을 주소 한 점으로 두어서, 진입 구간 효과가 최대 사업장 한 곳에 크게 좌우된다.
- 탄소 범위는 대상 묶음·배출계수·전환 가정에 따른 잠재량이며 관측값이나 통계적 신뢰구간이 아니다.
