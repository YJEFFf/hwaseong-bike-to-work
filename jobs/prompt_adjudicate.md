# 불일치 재판정 지시문

1차(A)·2차(B) 분류가 갈린 공고만 다시 판정한다. `prompt_classify.md`의 정의를 그대로 따르고, 아래 동점 규칙을 추가로 적용한다. A·B의 답은 참고만 하고, 판단은 입력 원문으로 한다.

동점 규칙
1. `필수`는 원문에 필수·필요·만·한해·있어야·소지자에 한함처럼 없으면 지원·근무가 안 된다는 표현이 있을 때만이다. "자차 출퇴근 가능자"처럼 강도 표현 없이 나열만 되어 있으면, 자격요건·필수 항목 아래에 있을 때 `필수`, 우대 항목 아래나 위치가 불분명하면 `우대`로 한다.
2. `출퇴근`은 출퇴근·통근·대중교통·교통편·외진 위치 같은 이동 이유가 원문에 있을 때만이다. "인근 거주자, 차량소지자 우대"처럼 거주지와 나란히 적기만 하고 이유를 쓰지 않았으면 `불명`이다. (2026-10-22 전수 검수 때 이 기준으로 통일했다. 처음 재판정 지시문은 이런 경우를 출퇴근으로 봤으나, 1·2차가 일치한 공고에는 적용되지 않아 기준이 갈렸다.)
3. `업무`는 직무 설명에 개인 차량으로 이동하는 일이 있을 때만이다(방문·라운딩, 배송·납품, 영업·출장, 현장 간 이동). 화물차·지게차·버스 등 회사 차량을 운전하는 직무에서 자차 이유가 없으면 `불명`이다.
4. 위 어느 것에도 근거가 없으면 `불명`이다.
5. `evidence`는 판정 근거를 입력 원문에서 그대로 옮긴다(80자 이내, ` / `로 구분). 우대조건 칸만 근거면 `[우대조건: 차량소지자]`.

출력: `{"공고번호": {"car_level": ..., "car_purpose": ..., "transit_barrier": ..., "shuttle": ..., "night_or_shift": ..., "evidence": ..., "note": "한 줄 이유"}}` 형태의 JSON 객체 하나.
