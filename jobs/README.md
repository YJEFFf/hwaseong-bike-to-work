# 채용공고로 본 자차 출퇴근 조건 (2026-10-22 추가 분석)

화성시 채용공고 원문을 AI로 읽어 "차가 없는 구직자가 불리한 조건"(자차 필수·우대와 그 이유)을 정리하고,
근무지에서 자전거망·버스 정류소까지의 거리, 구별 자전거 접근성(`commute/`)과 겹쳐 본다.

## 자료

- 고용24 채용정보 상세검색, 근무지역 화성시(41590), 2026-10-22 00시 게시 중 공고. 목록 5,512건 중
  고용24에 직접 등록된 공고(구인인증, `infoTypeCd=VALIDATION`) 3,475건을 분석한다. 민간 포털 연계 공고는
  고용24 상세 화면에 본문·우대조건·구가 없어 제외했다. robots.txt는 `/wk/` 경로를 허용한다. 요청 간격은 작업자당 1초다.
- 근무 예정지 좌표: 공고 상세 화면 지도 버튼의 경위도(`data-map-coor-x/y`).
- 경기버스정보(GBIS) 정류소·노선 경유 파일(2026-10-21 내려받음). 노선이 경유하는 정류소만 쓴다.
- 자전거망: `commute/scripts/00_restore_osm_nodes.py`로 노드 번호를 복원한 합집합망(공식 GIS + OSM).
- 비교 도시 수치(`results/region_compare_20261022.csv`): 고용24 검색 건수(정보제공처=고용24, 우대조건=차량소지자).

## 개인정보와 공개 범위

공고 원문에는 채용 담당자 이름·전화·이메일이 있다. `02_parse.py`는 담당자 영역을 읽지 않고, 본문의 전화번호·이메일은
지운 뒤에만 AI에 넣는다(공고 제목에 적힌 회사·고용센터 대표번호 2건은 개인 연락처가 아니어서 그대로 들어갔다).
원문·좌표는 `JOBS_DATA`(비공개 폴더)에만 두고, 이 폴더의 `results/`에는 집계만 올린다.

## 실행 (저장소 루트, `JOBS_DATA`=비공개 폴더)

```
python -X utf8 jobs/scripts/01_collect.py all      # 목록 → 상세 원문(gzip)
python -X utf8 jobs/scripts/02_parse.py            # 항목 추출, 담당자 정보 제외
python -X utf8 jobs/scripts/03_prepare.py          # AI 분류 대상 선정·배치, 규칙 기반 기준 분류
#   (입력이 바뀐 공고와 새 후보만 새 배치로 덧붙인다. 04는 뒤 배치의 입력·라벨을 쓴다)
#   AI 분류: prompt_classify.md로 1차(A, Claude Opus)·2차(B, Claude Sonnet)를 서로 모르게 따로 실행
#   → JOBS_DATA/labels/passA, passB/batch_*.json
python -X utf8 jobs/scripts/04_merge_labels.py     # 형식·근거 문장 대조, 일치도, 불일치 목록
#   불일치는 prompt_adjudicate.md로 재판정 → JOBS_DATA/adjudication.json
#   AI 검수(prompt_audit.md) 수정 → JOBS_DATA/audit_fixes.json
#   Claude 전수 확인(prompt_review.md, 852건을 원문 전체로 한 건씩) → JOBS_DATA/claude_review.jsonl, 다시 04 실행
JOBS_NET_ROOT=<복원 망 작업 폴더> JOBS_GBIS=<GBIS CSV 폴더> JOBS_COMMUTE_RESULTS=commute/results python -X utf8 jobs/scripts/05_analyze.py          # 구·직종·거리별 집계, 검증용 무작위 100건 시트
python -X utf8 jobs/scripts/06_figure.py           # 그림(보고서 그림 3)
python -X utf8 jobs/scripts/07_verify_sheet_html.py # 무작위 100건 시트를 원문과 나란히 보는 HTML(비공개 폴더)
```

AI 분류는 같은 입력에도 결과가 조금씩 달라질 수 있다. 그래서 두 모델의 결과를 비교하고, 근거 문장이 원문에 실제로
있는지 기계적으로 확인하며, 사람이 원문과 대조할 무작위 100건 시트(`verify_sheet_100.csv`)를 만든다.

## 2026-10-22 검증 기록

1. **파싱 오류 발견과 수정.** 원문 3,475건 전체에서 차·출퇴근 낱말이 AI 입력에 빠졌는지 대조했다. 두 가지가 나왔다.
   - 표 캡션('…을(를) 제공하는 표')을 지우는 정규식이 쉼표가 든 앞 칸 내용까지 지웠다. 그 결과 '기타 우대사항' 71건이 잘리거나
     엉뚱한 내용으로 저장됐고, '우대조건' 26건(그중 '차량소지자' 체크 15건)이 빠졌다.
   - '그 밖의 희망사항' 칸(464건이 작성, 그중 147건에 차·출퇴근 문구)을 아예 저장하지 않았다.
   - 캡션은 `<caption>` 태그째 지우도록 고치고 `other_wish` 칸을 더했다. 본문은 바뀌지 않았다.
2. **후보 재선정.** `other_wish`를 후보 판정에 넣고, '자동차 출근', '차량을 이용' 같은 표현을 정규식에 더했다.
   - 그때 후보 밖이던 2,633건 가운데 차·운전·출퇴근·교통·거주 낱말이 있는 793건은 Claude가 문맥을 한 건씩 읽었다.
     놓친 자차 조건은 2건이었고, 넓힌 정규식으로 둘 다 잡힌다. 나머지 1,840건에는 해당 낱말이 없었다.
     최종 후보 밖 2,623건은 6번에서 낱말과 상관없이 원문을 모두 다시 읽었다.
   - 후보는 775 → 852건이 됐다. 새 후보 77건과 입력이 바뀐 142건, 모두 219건은 1·2차 AI 분류를 다시 했다.
3. **AI 검수(prompt_audit.md).** 처음 775건을 검수용 AI가 다시 읽어 24건을 고쳤다(audit_fixes.json).
4. **Claude 전수 확인(prompt_review.md).** 852건의 원문 전체를 기존 라벨을 보지 않고 한 건씩 판정했다.
   - 다섯 항목이 모두 기존 라벨과 같은 공고는 813건이었다.
   - 다른 39건은 원문을 다시 읽어 정했다. 그중 6건은 Claude 판정이 틀려 고쳤다(숙직·교대 표기 누락 4, 출퇴근 유류비 문구 2).
   - 최종 근거 문장은 852건 모두 원문 대조를 통과했다.
5. **직무 이동 기준 고침(팀원 지적).** 첫 기준은 회사 화물차로 배송하는 운전 직무처럼 차가 직무에 들어가는 공고 27건을
   '이유 불명'으로 남겨 본 지표에 넣었다. 차가 직무에 들어가면 회사 차량을 쓰든, 자차 조건 이유로 출퇴근을 적었든 빼도록 바꿨다.
   - 이동 판정 111건을 원문으로 다시 읽어 이동을 보여 주는 문구(`job_travel_evidence`)를 붙였다. 105건 모두 원문 대조를 통과했다.
   - 근거가 약한 7건(전화 응대 중심 영업관리 사무, 장소 없는 '설치', 모집직무 나열에만 있는 '운송' 등)은 이동 아님으로 고쳤다.
   - 이동 아님 562건 가운데 이동 낱말이 있는 123건을 다시 읽어 방문요양센터 사회복지사 1건을 이동으로 고쳤다.
   - '시운전'(장비 시험 가동), 설비 운전, 사업장 안 지게차·굴착기 운전은 차 운전으로 보지 않는다. 시운전을 근거로 이동 판정한 공고는 없었다.
   - '운전가능자(대중교통 없음)' 1건은 차 소유·이용을 적지 않아 자차 조건 없음으로 고쳤다.
6. **두 번째 전수 읽기(팀원 요청).** 낱말 검색이나 표본에 기대지 않고 원문을 처음부터 다시 모두 읽었다.
   - 본 지표에 든 567건은 라벨을 바꾼 공고가 없었다. 직무 이동 여부가 갈릴 수 있는 8건은 경계 사례에 더했다.
   - 최종 후보 밖 2,623건에서 놓친 자차 소유·이용 조건은 없었다. 복리후생에 주유비·유류비·차량유지비 지원만 적은 공고는
     코드북대로 자차 조건으로 세지 않았다. 후보 안에서도 이 문구만 있는 공고는 '없음'이다. 우대·필수로 센 공고에는 모두
     차량소지자 칸 체크나 차 소유 문구가 따로 있다.
   - 판단이 갈릴 수 있는 22건(이동 예 8건, 이동 아님 13건, 자차 조건 1건)을 모두 반대로 바꿔도 본 지표는 15.9~16.6%
     (서부 18.2~19.0%, 동부 5.8~6.1%, 서부/동부 3.1배)다.
7. **결과(본 지표 = 자차 필수·우대 가운데 직무 이동 공고를 뺀 값).**
   - 자차 필수·우대 672건(19.3%), 직무 이동 105건을 뺀 567건(16.3%), 그중 출퇴근·대중교통 이유 179건.
   - 서부 18.7%, 동부 6.0%. 같은 직종끼리 비교한 승산비는 2.81(1.98~3.98).
   - 출퇴근·대중교통 이유를 적은 공고만 세는 민감도(`commute_only_sensitivity`)에서도 서부 5.9%, 동부 1.7%, 승산비 2.91(1.56~5.42).
   - 자전거 노선 150m 안 일터 7.1%, 그보다 먼 일터 17.4%. 직종과 서부·동부를 함께 맞추면 승산비 1.50(0.96~2.36).
   - 본 지표에 든 공고 가운데 대중교통 불편을 적은 29건은 모두 서부에 있다.

판정은 모두 AI(Claude)가 했고 사람이 전수 확인한 것은 아니다. 무작위 100건 시트(`verify_sheet_100.html`)로 사람이 확인할 수 있다.
